# PixPut Project Precepts

This overlay sets the cross-cutting rules every agent in this repo applies, on top of the project constitution. The project constitution governs project-specific decisions; this overlay governs how agents behave across phases.

When a precept and the project constitution conflict, the project constitution wins for project-scoped topics (domain language, allowed APIs, performance budgets) — the precepts win for cross-cutting agent behaviour (how to plan, what to read, what to write, when to halt).

Authoritative project constitution lives at [`roadmap/product/constitution.md`](../roadmap/product/constitution.md). The agent-facing constitution at [`.claude/constitution.md`](./constitution.md) only wires source paths and package namespaces — it does not override the product constitution.

---

## Principle 1 — Native Swift / macOS Stack

This project is a single-platform Swift application (macOS 14+, AppKit + SwiftUI for Settings, the Accessibility API, CoreGraphics, IOKit, ScriptingBridge). There is no .NET, no Electron, no JavaScript runtime, and no cross-platform abstraction layer.

**Rule**: before introducing a new abstraction, agents MUST:

1. Read [`agents/stacks/swift.md`](../agents/stacks/swift.md) — the Swift stack agent defines test frameworks, build commands, idioms, and patterns for this codebase.
2. Read [`roadmap/product/constitution.md`](../roadmap/product/constitution.md) Principle II — window identity is layered. A new identity capability is a new `WindowIdentityProvider` in `Core/Identity/AppProviders/`, never a relaxation of the layered strategy.
3. Match Apple framework patterns (AppKit, SwiftUI, Combine, async/await) before inventing new ones. If a system framework already does what you need, use it.

Bespoke abstractions outside `Core/Identity/AppProviders/` extension point require justification recorded in the plan's Complexity Tracking table.

The `package-namespaces` value in `.claude/constitution.md` is `PixPut.*` — Swift modules / target names follow this convention.

## Principle 2 — Project Documentation Adherence

This project's load-bearing documents live under [`roadmap/product/`](../roadmap/product/) and the per-feature folders therein:

- `roadmap/product/vision.md` — what we're building and why
- `roadmap/product/constitution.md` — the 7 numbered principles (load-bearing)
- `roadmap/product/roadmap.md` — sequencing
- `roadmap/product/features.md` — feature inventory
- `roadmap/product/<NNN>-<feature>/spec.md` — feature spec
- `roadmap/product/<NNN>-<feature>/plan.md` — implementation plan
- `roadmap/product/<NNN>-<feature>/research.md` — design research (e.g., macOS API choices)
- `roadmap/product/<NNN>-<feature>/data-model.md` — entity definitions
- `roadmap/product/<NNN>-<feature>/quickstart.md` — manual-test checklist
- `roadmap/product/<NNN>-<feature>/tasks.md` — generated by the technical-planner

**Rule**: before planning, writing tests, writing code, generating a checklist, or analyzing changes, an agent MUST read the constitution + the relevant feature folder. Treat those documents as authoritative project-specific guidance.

If a feature folder is missing required artefacts for the current phase, halt with a specific error naming the missing file.

## Principle 3 — Architecture Source = Directory

This project does not use any CJCO architecture or platform MCP server. The C4 model lives at [`roadmap/arch/c4/`](../roadmap/arch/) (directory mode). The arch root is currently sparse — the architect agent populates it as architecture decisions are made.

**Rule**: the architect agent reads `agents.architecture.source: directory` from `.claude/constitution.md` and uses file I/O against `<c4_root>` rather than MCP calls. The code-reviewer ignores the (omitted) `agents.platform` block — there is no platform-package ecosystem to consult.

If `agents.architecture.source` is missing from `.claude/constitution.md`, halt with: `BLOCKING: no architecture source configured.`

## Principle 4 — Project Constitution Authority

Every agent MUST read [`roadmap/product/constitution.md`](../roadmap/product/constitution.md) before acting on the project's code. Its 7 principles (native macOS / layered identity / idempotence / local-only / graceful permissions / direct distribution / performance budgets) constrain what agents may propose.

A principle CAN be deviated from in a single feature only when the feature plan's Complexity Tracking table documents (a) which principle, (b) why the simpler path was rejected, (c) a specific revisit trigger. Agents propose; humans decide.

## Required Inputs (Hard-fail)

Before proceeding with any spec, plan, task, analysis, or implementation work, agents MUST verify all three inputs are present. If ANY is missing, halt with the corresponding error — do not attempt to recover or proceed with partial inputs.

| Input | Path | On missing |
|---|---|---|
| Project precepts overlay | `.claude/project-precepts.md` | Halt: "Project precepts missing — re-install `@cerebral-juice-co/claude-agents` or restore this file from version control." |
| Agent-facing constitution | `.claude/constitution.md` (must contain a valid `agents:` block) | Halt: "Constitution missing or `agents:` block invalid at `.claude/constitution.md`." |
| Project constitution | `roadmap/product/constitution.md` | Halt: "Project constitution missing at `roadmap/product/constitution.md`." |

These checks apply to every engineering and review agent (`architect`, `technical-planner`, `tdd-developer`, `software-developer`, `qa`, `qa-validator`, `code-reviewer`, `security-reviewer`, `devops`, `documentation`, `rubric-evaluator`, `telemetry-feedback`) and every project-scoped slash command. Stack and product-research agents inherit context from their invoker and do not need to re-verify.

## Appendix: Agents Configuration

The agent system reads source bindings from `.claude/constitution.md`. The required form for this project is:

```yaml
agents:
  architecture:
    source: directory
    c4_root: roadmap/arch/c4
    roadmap_root: roadmap/arch
    adr_root: roadmap/arch/decisions
  # No `platform:` block — this project has no CJCO platform dependency.
  package_namespaces:
    - PixPut.*
```

### Resolution rules

1. The architect reads `agents.architecture.source`. If missing, halt with `BLOCKING: no architecture source configured`.
2. `source: directory` is the only supported mode for this project. If `source: mcp` is set, the architect halts: the CJCO arch MCPs are .NET-oriented and produce off-target guidance for Swift/macOS.
3. `c4_root` must exist on disk before any C4 read. The architect creates it on first run if absent (with an `Architect Review` block annotation noting the creation).
4. The code-reviewer agent's "platform pattern consultation" pass is a **no-op** in this project — it does not invoke any `mcp__platform-mcp__*` tool. It still validates against Swift idioms and the project constitution (see Principle II — layered identity, Principle VI — private CGS isolation).

### Why this differs from the v4.x default

The upstream `@cerebral-juice-co/claude-agents` package targets CJCO Platform .NET workloads by default. PixPut is a standalone macOS Swift app with no CJCO platform integration. This overlay strips the .NET-specific gates and substitutes Swift/macOS-appropriate ones without changing the agent orchestration topology (architect → planner → TDD → QA → reviewers still applies).
